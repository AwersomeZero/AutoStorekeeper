## Описание
Данный скрипт создан "на коленке" для перевода MaterialList из мода Litematica в таблицу Excel. Он предназначен для организаторов больших временных складов под мегапроекты масштаба сервера PEPELAND и позволяет быстро определить точное количество сундуков/шалкеров и табличек. Помимо большего удобства работы с листом благодаря табличному процессору и ускорению стройки склада для крупного проекта (спавн/хаб и т.п.), к списку добавляются столбцы "Стаки" (кол-во стаков с запасом), "Даблчесты" (число двойных сундуков с запасом) и "Шалкербоксы". Также в скрипте реализована особая сортировка блоков - она основана на принципах логистики и оптимизации пути, сокращая время на поиск ячейки с искомым блоком. Гайдлайны к созданию склада и методическое обоснование данной сортировки описано ниже. Краткий обзор метода сортировки:
 * В начале списка находятся все блоки, занимающие более одного шалкербокса. Они занимают первый отдел склада.
 * В середине списка находятся блоки объёмом от 1 до 27 стаков. Они занимают второй отдел склада
 * Оставшуюся часть списка занимают более мелкие по количеству ресурсы. Они занимают третий отдел склада.
 * Внутри отделов ресурсы отсортированы по рубрикам, категориям и подкатегориям из творческого инвентаря. Таким образом, все блоки из одного материала будут находиться рядом друг с другом, образуя подкатегорию (дубовые доски, люки, двери и т.п.), все подкатегории будут образовывать уже более крупную категорию (деревянные блоки, каменные блоки, керамика и т.п.), а все категории образуют рубрику из инвентаря креатива (строительные блоки, природные блоки, функциональные блоки и др.)

## Работа с программой в web интерфейсе
1. Сохраните из схематики materiallist: Размещённые голограммы -> Настроить -> Список материалов
-> (с зажатым Alt) Экспорт. JSON файл запишется в minecraft/config/litematica. 
2. Откройте web интерфейс программы по ссылке: https://awersomezero.github.io/AutoStorekeeper/
3. Перенесите данный materiallist в указанную область, либо выберите файл по кнопке.
4. Готово! Результат можно сохранить себе на ПК, либо посмотреть прямо в браузере

**Если произойдёт ошибка и какой-либо блок/предмет не будет найден в базе данных, информация появится в текстовом окне логов. Сообщите об этом создателю.**

### Введение в теорию складостроения
Главная проблема, которая возникает при постройке мегапроектов уровня сервера PEPELAND (пример: проекты Горгорода, Унтеса, спавны/хабы, другие общие и частные проекты) - большое разнообразие блоков. К примеру, один из самых трудоёмких проектов PPL10 - Хаб МП2, содержит 385 различных блоков. Если создать склад для подобного проекта не составит труда (выгрузить material-list, поставить нужное количество сундуков, разметить таблички), то вот использовать такой склад - большая проблема. Чтобы начать строить слой или отдельную часть проекта, необходимо:
1. Пройтись по всему складу и собрать нужные ресурсы.
2. Поставить по схеме указанные блоки.
3. Вернуть оставшиеся ресурсы на свои места.
4. Повторить алгоритм.

До 2/3 времени в данном алгоритме может уходить на поиск ресурсов на складе. Даже используя мод Pochatok с командой /singsearch (поиск по названиям на табличках) временные затраты остаются высокими. 
В первую очередь - **расположение сундуков**. Если хранилища расположены далеко друг от друга, то игрок потратит большое количество времени на передвижение между ними. Если же игрок ищет таблички по ключевым словам, а не полному названию ("каменный"), то имеется риск потратить ещё больше времени в попытках найти нужное хранилище. Данный фактор также играет роль во время складирования добытых ресурсов. Также важно учитывать **фактор внимания**. Игрок может не заметить нужный блок/табличку и искать его в другом месте.
Наиболее очевидное решение данной проблемы - **улучшение интуитивной навигации** на складе. Если расположение ресурсов будет систематизировано и логически обосновано, то человеку будет проще на нём ориентироваться. Это объясняется стремлением мозга к системности и упорядоченности. До существования утилиты **ASK-AutoStorekeeper** создать подобный склад было достаточно проблематично. Для этого необходимо:
* сформулировать методику сортировки склада (как наиболее оптимально расположить все ресурсы, чтобы повысить его эффективность и удобство использования),
* создать список ресурсов для данного склада (с применённой методикой сортировки),
* создать схему склада для данного проекта,
* построить склад.
Вы можете самостоятельно заняться работой по формулированию методики сортировки. Здесь же мы предлагаем свой подход к данной проблеме и свою методику сортировки.

### Комбинированная сортировка (Категориально-количественная сортировка ресурсов)
Данный метод сочетает в себе интуитивную сортировку ресурсов по категориям и удобство масштабирования склада в зависимости от количества ресурсов. Он неоднократно применялся при постройке складов для различных общих проектов во время 10 сезона Pepeland. Сначала весь набор ресурсов разделяется на три укрупнённые группы по количеству:
1. **Большая группа** (каждого типа ресурсов больше 27 стаков, т.е. больше 1 бочки/шалкера).
2. **Средняя группа** (каждого типа ресурсов меньше 27 стаков, но больше 1  стака, т.е. вмещается ровно в 1 бочку/шалкер).
3. **Малая группа**  (каждого типа ресурсов меньше 1 стака, т.е. занимает ровно одну ячейку).

Для каждой группы имеется возможность масштабировать склад (добавить больше сундуков для блока большой группы, увеличить кол-во бочек для средней группы и т.п.) Внутри каждой группы уже идёт интеллектуальная сортировка по рубрикам, категориям и подкатегориям. Данная сортировка составлялась вручную на основе инвентаря творческого режима Minecraft. Исключением являются некоторые медные блоки - их легче объединить в одну категорию. Подробное разделение:
* **Креативная рубрика.** Делится по рубрикам из инвентаря креатива (природные блоки, строительные блоки и т.п.). Содержит в себе категории.
* **Категория.** Делится по видам материала изделия (дерево, камень, медь и др.). Содержит в себе подкатегории.
* **Подкатегория.** Делится по конкретным материалам (дуб, ель, берёза и др.). Содержит в себе конкретные блоки.

При использовании данной схемы сортировки навигация по складу становится более интуитивной и понятной. Таким образом сокращается время, затрачиваемое на перемещение по складу и поиск нужного ресурса. Для улучшения визуального восприятия рекомендуется не только помечать хранилища табличками, но и ставить **примеры блоков** над этими хранилищами. На скриншоте выше вы можете видеть пример построения склада по такому принципу.

### Общие советы по созданию склада
* Рекомендуется создавать склад на отдельной платформе с лестницами к нему, если хранилища будут рядом с проектом. Это позволит построить склад ближе и не мешать постройке ландшафта под ним.
* Выбирайте нейтральные и недорогие блоки для оформления склада. Так его будет дешевле и быстрее воздвигнуть.
* Обязательно установите рабочие станции для крафта/переделки предметов на месте, а также эндер сундуки и места для быстрой выкладки ресурсов, которые необходимо отсортировать.
* Рекомендуется установить особые хранилища с едой, тотемами, подмостками и другими полезными ресурсами, которые могут пригодиться во время строительства.
* Храните служебные ресурсы (материалы для склада, таблички, бочки, красители) отдельно с пометками "Не трогать".
